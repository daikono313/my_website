## 今週のアクション

- 🔴 **Snowflake の BCR バンドル 2026_07 の影響を確認する** — 10/16 から既定で有効。GRANT OWNERSHIP の移譲ルール、CORTEX_MODELS_ALLOWLIST の扱い、BITCOUNT の戻り値型などが変わる。必要なら一時的にオプトアウトする（[出典](https://docs.snowflake.com/en/release-notes/bcr-bundles/2026_07_bundle)）
- 🔴 **Snowflake Python Connector を 5.0 未満に固定し、5.0 の互換性を確認する** — `region` などのパラメータやモジュールが削除され、証明書の失効確認が OCSP から CRL に変わった（[出典](https://docs.snowflake.com/en/release-notes/clients-drivers/python-connector-2026#version-500-oct-15-2026)）
- 🔴 **Trino 484 へ上げる前に破壊的変更を確認する** — GRANT/REVOKE がユーザー名の大文字小文字を区別するようになり、JSON・interval の意味も変わった（[出典](https://github.com/trinodb/trino/releases/tag/484)）
- 🔴 **Databricks の Knowledge Assistant / Supervisor Agent の移行を計画する** — どちらも legacy 扱いになった。移行先は Agent Bricks CLI か Genie Agents（[出典](https://docs.databricks.com/aws/en/release-notes/product/2026/october#knowledge-assistant-and-supervisor-agent-are-now-legacy)）
- 🔴 **dbt の SCIM トークンを API で作っている場合は手順を見直す** — PAT やサービストークンでは作成できなくなった（[出典](https://docs.getdbt.com/docs/dbt-versions/dbt-cloud-release-notes#october-2026)）
- 🟡 **BigQuery の生成 AI 関数にトークンのクォータを設定する** — 日次の上限をプロジェクト単位・ユーザー単位で設定できるようになった（[出典](https://cloud.google.com/blog/products/data-analytics/using-bigquerys-generative-ai-cost-management-features)）

## 横断トレンド

**競争の焦点が「どのモデルを使えるか」から「エージェントに渡すコンテキストを誰が押さえるか」へ移っている。** Snowflake は Horizon Context で、Power BI・Tableau・dbt・Databricks など外部18ソースのメタデータとリネージを自社カタログに取り込んだ。Google は Lakehouse のカタログフェデレーションで、Gemini から Unity Catalog と Snowflake Horizon のデータを移動させずに問い合わせられるようにした。Databricks も、外部エンジンから管理 Delta テーブルへの書き込みと、ビューの参照を GA にしている。各社とも「自社カタログを中心に、他社のデータも扱える」形を目指していて、Iceberg REST のような共通カタログ API がその接続方式になりつつある。

**エージェント開発の部品が一気にそろった。** Snowflake の Cortex Agent SDK、Google の Data Agent Kit（MCP サーバーとスキルを Claude Code や Codex 向けに提供）、Databricks の Skills API と agent memory、AWS MWAA の AI エージェントスキル、dbt Wizard のリモート MCP への既定接続が、同じ週に出た。データ基盤チームの仕事に「エージェントが安全に操作できる面（権限・スキル・記憶）を整える」ことが加わってきている。

**AI の利用統制も製品機能になってきた。** BigQuery の AI 関数のトークンクォータ、Databricks のモデル・MCP へのレート制限、Snowflake の BCR での CORTEX_MODELS_ALLOWLIST の扱いの変更と、コストと権限のガードレールが各社でそろってきた。SQL から LLM を呼ぶ処理を本番で使うなら、クォータと監視の設計を先に決めておきたい。
